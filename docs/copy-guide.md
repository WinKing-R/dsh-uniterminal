# 文案规范（UniTerminal 前端）

> 这是前端文案的**唯一事实来源**。新增界面文案先读这份；与本文件冲突的既有文案，**以本文件为准**。
> 依据：`docs/superpowers/plans/ledger-m0.md` 的既有裁定 + 本文件列出的六条待修问题。

## 一、术语表（一个字都不能用别的说法）

| 概念 | 统一用 | **不要用** | 说明 |
|---|---|---|---|
| SSH 密码 | **密码** | 口令（"口令"只允许出现在"私钥口令"这个词组里） | "口令保护"是已取消的加密能力（台账 D-2a），**界面里不许出现** |
| 一次已建立的 SSH 连接 | **会话** | 连接（"连接"只用来表示"连过去"这个动作） | 会话栏 / 断开连接 / 会话已结束 / 新建会话 |
| 结束一条会话 | **断开连接** | 关闭会话（同一个动作的两种说法，统一成前者） | 用户的原话；台账 M9-11 与 acceptance-m2a 都用它 |
| 测一次连通性 | **测试连接** | 连接测试 | 行内那个短按钮写「测试」；结果文案用「连通 ✓ / 连通 ✗」 |
| 主机条目 | **主机** | 服务器 | 远端那台机器叫「远端主机」 |
| 分组 | **分组** | 分组路径（M10 之后数据模型已是 groupId 树，没有"路径"这回事） | 多级用 `/` 分隔 |
| 文件类型 | **其他** | 其它 | |
| 凭据的存储方式 | **（不分档）** | 明文模式 / 加密模式 / 严格档 / 简单档 | M65：旧的加密档整套删除，现在没有"档位"之分 |
| 密码存在哪 | **系统密码箱** / **本机文件** | 保险库 / 凭据库 / 加密文件 / 密钥环 | M66：密码箱是**操作系统**提供的功能（Windows 凭据管理器 / macOS 钥匙串 / 系统钥匙环）；插件不提供"保险库"这类自造能力 |
| 新建一个主机条目 | **添加主机** | 新建主机 | 分组用「新建分组」，会话用「新建会话」 |

## 二、句式

### 2.1 失败提示
统一形状：**`<动作>失败：<原因>（<下一步>）`**

- 动作写**用户做的事**：「删除主机失败：」「导入配置失败：」「连接主机失败：」「断开连接失败：」「保存配置失败：」「信任主机失败：」「上传失败：」「下载失败：」「建立隧道失败：」
- 允许另一种形状：**`<对象>不可用：<原因>`**（例如「主机列表不可用：」）——只在"东西本身读不到"时用，不要滥用。
- **原因必须说清是什么，下一步必须说清怎么做**。宿主已经给了分类文案（超时 / 拒绝 / DNS / 不可达 / 指纹 / 认证），直接用，不要自己再翻译一遍。
- **不许把内部字段名暴露给用户**。以下写法一律禁止：
  - ❌「连接失败：响应缺少 session.id」
  - ❌「连接失败：响应缺少 ws 地址」
  - ❌「复制会话失败：响应缺少 session.id」
  - ❌「接管失败：该会话缺少 ws 地址」
  - ❌「建立失败：响应缺少 tunnel」
  - ❌「宿主没有返回新分组的 id」
  → 一律改成 **「服务返回异常，请重试」**，**原始细节写进 diag**（`reportClient`），不显示在界面上。

### 2.2 成功提示
形状：**「已<完成的事>」**，例如「已删除 X」「已导入 N 台主机」「已保存配置」「已交给浏览器下载：X」。
成功提示走 `setOk`（绿色），失败走 `setNotice`（红色）。

### 2.3 状态说明
不是操作反馈，也不是失败：例如「正在连接 user@host:port…」「会话已结束：宿主上已经没有这条会话」。
- 状态说明**不用错误色**，用中性色（`.uniterminal-hint`）。
- 状态说明**不自动消失**（只有"操作反馈"才走 `useNotice` 的 6 秒过期）。

### 2.4 凭据存在哪（表单页常驻小字）

这一段是**常驻**的状态说明（不是操作反馈）：放在密码框下面那一带的小字里，
**不另起一块横幅**。文案随**后端**变化，五句都在 `src/store/credential-backend.ts` 里定义，
界面、服务端响应、测试、文档四处一致：

| 情况 | 文案 |
|---|---|
| Windows 密码箱 | 密码保存在 Windows 凭据管理器 |
| macOS 钥匙串 | 密码保存在 macOS 钥匙串 |
| Linux 钥匙环 | 密码保存在系统钥匙环（Secret Service） |
| 没有系统密码箱（文件后端） | 这台机器没有可用的系统密码箱，密码明文保存在本机凭据文件（仅当前账户可读） |
| 曾用密码箱、现在降级 | 系统密码箱暂时不可用，已临时改用本机文件保存 |

> 表单页那一行常驻小字在**文件后端**下用的是验收单锁定的那句原文
> （「密码以明文保存在本机凭据文件，受 Windows 账户权限保护」）——
> 那时密码确实在本机文件里；**密码箱后端**下换成表里对应平台那一句。
> 详见 `docs/acceptance-m2a.md` 判据 3 的注记。

## 三、标点

| 用途 | 用 | 不要用 |
|---|---|---|
| 引用一个具体名字 | **「」** | "" '' （） |
| 补充说明 | **（）** | —— |
| 省略号 | **…**（单个） | ... …… |
| 破折号 | **——** | -- |
| 分段分隔（状态栏那种一行的指标） | **│** | |
| 详情里的次级信息（进度行的「· 已用 3s」） | **·** | |

中文与英文/数字之间留一个空格（「已导入 3 台主机」）。

## 四、不许出现在界面上的东西

- **工程编号**：「M1 只支持 SSH 连接：」这种里程碑编号是给开发者看的，不给用户。
  已取消的能力同理：「口令保护」「凭据库」这类词不许出现（界面只说明"密码以明文保存在本机凭据文件"）。
  **「加密」「主密码」「解锁」「锁定」「明文模式」同样不许出现**（M65：旧的加密档已整体删除，
  现在只有一种存储、没有"档位"之分；界面不描述不存在的能力）。
- 内部字段名（见 §2.1）。
- **把操作系统密码箱说成插件自己的能力**：「保险库」「凭据库」「加密文件」这类词不许出现——
  密码存进的是**操作系统**的密码箱（Windows 凭据管理器 / macOS 钥匙串 / 系统钥匙环），
  插件自己不实现任何加密（M66）。
- 调试信息、堆栈、URL。

## 五、新增文案时

1. 先查这张表，用词要对得上。
2. 失败提示先问自己：**用户看到这句之后，知道下一步做什么吗？** 不知道就补。
3. 中文文案不出现内部标识符（`session.id`、`ws`、`tunnel`…）。
4. 改完跑 `pnpm test`——既有断言是按源码文本锁的，改文案要同步改断言，但**保留它要防的回归意图**。
