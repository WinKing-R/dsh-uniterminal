# M1 端到端验收单

> 重启 DSH 后按顺序做。M1 代码部分已完成（9 任务 / 81 用例 / typecheck 与 build 均 0）。

## 预期内的行为变化（不是 bug）

**未知主机会被默认拒绝。** `known_hosts` 已接入传输层，首次连接任何主机都会报 `uniterminal: unknown host key for <host>:<port> (<指纹>)`，点「信任该主机并重试」后才放行，指纹会写入 `~/.dsh/uniterminal/known_hosts.json`。

## 五条判据

1. **列表先出现**：右栏 `+` 打开 UniTerminal，应直接看到主机列表（不是手填表单）；空态有「从 ~/.ssh/config 导入」按钮
2. **导入可用**：点它，应提示「已导入 N 台主机…」，列表出现分组为 `ssh-config` 的缩进条目（你的 `~/.ssh/config` 已存在）
3. **点条目预填**：点其中一条，进入终端表单且 host/port/user 已填好；密码需手输（M1 不持久化凭据）
4. **指纹拦截与信任**：连一台未信任主机 → 报 `unknown host key` → 出现「信任该主机并重试」→ 点击后应连上
5. **二次连接直接进**：同一主机再连一次，不再要求信任

## 日志位置

`~/.dsh/uniterminal/diag.log`（宿主侧 + 浏览器侧事件；`session.created` / `ws.upgrade` / `client.ws-opened` 都在里面）。

## M1 明确未做（进 M2）

- 导入的 `IdentityFile` / `ProxyJump` / `LocalForward` **不落盘**：键认证的主机导入后仍需手输密码
- 无「返回列表」按钮：缺少会话关闭端点，返回列表会留下孤儿会话
- 密码仍以明文经 loopback 路由传输，无凭据保险库
- 重连次数不因成功而清零（每会话一生最多 5 次），长时间会话经历多次抖动后需手动重连
## 追加判据 6 · 手动添加主机（M1-10）

重启后 UniTerminal 工具栏应有三个按钮：`从 ~/.ssh/config 导入`、`手动连接`、`添加主机`。

1. 点「添加主机」→ 列表上方展开内联表单（名称/主机/端口默认 22/用户默认 root/分组）
2. 名称留空点保存 → 前端提示「名称不能为空」，已填内容不丢
3. 填 名称=测试 / 主机=192.0.2.1 / 端口=22 / 分组=测试/子组 → 保存 → 提示「已添加 测试」，列表出现「测试」且缩进在「测试 / 子组」下
4. 该条目应写入 `~/.dsh/uniterminal/profiles.json`，且文件内不含任何口令字段
## 追加判据 7 · M1-12/13/14 修复（重启后验）

### 7a 删除主机（原报 SyntaxError）
列表里某台主机点「删除」（建议先加一台测试主机 `__tmp__` 再删它）：应提示「已删除 …」并从列表消失，**不再出现 `Unexpected token 'o'`**。

### 7b 终端随侧边栏自适应
1. 连上一台主机，拖动侧边栏宽度 → 终端列数应随之变化（终端里跑 `stty size` 能看到列数跟随）
2. 跑 `top` 铺满屏幕，退出 top 后 → **不应残留重叠文字**
3. 收起再展开侧边栏 → 终端应重新 fit，不出现错行

### 7c 分组成为真实体
1. 「新建分组」输入 `测试/子组` → 列表出现空分组「（空分组）」
2. 某主机行「移入分组」输入 `测试/子组` → 该主机移动到分组下
3. 点分组旁的「删除分组」→ 分组消失，**里面的主机仍在**（回到根层），profiles.json 里主机未被删除
4. `~/.dsh/uniterminal/profiles.json` 根上应出现 `folders` 字段
