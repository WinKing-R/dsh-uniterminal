## 判据 1 · 记住密码闭环（核心）
1. 点一台主机 → 表单里勾选「记住密码」（默认已勾选），密码框右侧有眼睛按钮可切换明文/密文
2. 输入密码 → 连接成功
3. 断开连接 → 回到列表，该主机行应出现「已记住」标记
4. 再点同一台 → **密码框留空，直接点连接应成功**（密码由宿主从凭据文件读取，永远不会填入输入框——这是设计）

## 判据 2 · 未保存密码时的提示
选一台**没连过**的主机，密码留空直接连接 → 应提示「该主机尚未保存密码，请输入一次并连接，之后会自动记住」，而不是 `password required` 或 `SyntaxError`。

## 判据 3 · 明文存储的事实告知
表单页应常驻一行小字：`密码以明文保存在本机凭据文件，受 Windows 账户权限保护`。界面上**不应出现**「加密」「已加密」「主密码」「解锁」「锁定」等字样。
> **M66 注记（公开仓库姿态：接操作系统密码箱）**：上面那句判据**原文保留，不改写**。
> M66 起凭据优先交给**操作系统密码箱**（Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service），
> 插件**自己不实现任何加密**；这时那句"密码以明文保存在本机凭据文件"**已经不准确**（密码并不在本机文件里）。
> 因此表单页那一行常驻小字**按后端变化**：
>
> - **文件后端**（这台机器没有可用的系统密码箱）→ 仍是本判据那句**原文**；
> - **系统密码箱后端** → 「密码保存在 Windows 凭据管理器」/「密码保存在 macOS 钥匙串」/
>   「密码保存在系统钥匙环（Secret Service）」；
> - **降级**（曾用密码箱、现在临时改用本机文件）→「系统密码箱暂时不可用，已临时改用本机文件保存」。
>
> 判据的后半句（界面里**不应出现**「加密」「已加密」「主密码」「解锁」「锁定」）**继续有效**：
> `test/client/notice-usage.test.ts` 里那条剥注释后的反向锁照旧守着。
> 另有一条新的诚实性要求：系统密码箱此刻不可用时，界面要给
> 「系统密码箱不可用，请稍后重试」，**不能**说成「请输入密码」（那句话会骗用户以为密码没记住）。

## 数据落点

| 文件 | 内容 |
|---|---|
| `profiles.json` | 主机信息 + `remember: true|false`，**绝不含密码** |
| `credentials.json` | `{ version, entries: { "profile:<id>": "<口令>" } }` （明文） |
| `security.json` | `{ "version": 1, "mode": "plain" }` |

> **M66 注记（数据落点）**：上面那张表是**历史原文**，保留不改写。M66 之后：
>
> - `security.json` 多一个 `storage` 字段（`"keychain"` / `"file"`），记下"密码存在哪"；
> - `credentials.json` **只在没有系统密码箱的机器上存在**——有系统密码箱时，
>   旧明文库会**逐条搬进密码箱然后删掉**，不留明文副本；
> - 有系统密码箱时，密码落在**操作系统密码箱**里（Windows 凭据管理器 / macOS 钥匙串 /
>   Linux Secret Service，service `dsh-uniterminal`），不在本仓库的任何文件里；
> - `vault.bin` 那行仍只用于**识别与清理**，永远不被读取。

## 已知限制

- 明文保存：防护仅依赖 Windows 账户目录权限（NTFS ACL）；`chmod 0600` 在 Windows 上无效（已实测确认）
- 无终端锁屏：离开座位时已连接的会话没有保护（你已决定暂缓）
- 两档互转已取消，降级是单向的
