# M2b + M2c 验收单（私钥登录 / 编辑主机 / 测试连接）

> 代码侧：195 用例 / typecheck 0 / build 0。重启 DSH 后验收。

## 判据 1 · 测试连接（最快，先验这条确认接线生效）
1. 列表里任意一行点「测试」→ 按钮变「测试中…」→ 行内出现「连通 ✓ <ms> ms」
2. 把某台主机的端口改成一个不存在的端口（如 59999）再测 → 应显示「连通 ✗ <错误原文>」
3. **不应**因为点了几次「测试」就在宿主里堆出会话（`curl 127.0.0.1:<port>/api/uniterminal/sessions` 应为空或只含你手动打开的）

## 判据 2 · 编辑主机
1. 点某行「编辑」→ 表单预填现值为「编辑 <名称>」→ 改别名或端口 → 「保存修改」→ 列表立即更新
2. **关键**：编辑前若该行有「已记住」或「私钥」标记，编辑保存后标记**必须还在**（这验证整份回写，避免字段被静默清空）
3. 编辑一台在分组里的主机 → 保存后它**仍在原分组**，没有被踢回根层

## 判据 3 · 私钥路径方式登录
1. 编辑或新增一台主机 → 「认证方式」选「私钥」→ 填 `私钥文件路径`（例如 `C:/Users/<you>/.ssh/id_ed25519`）→ 保存
2. 列表该行应出现「私钥」标记
3. 点连接 → **密码框留空也能连上**（前提：该主机确实接受这把公钥）
4. 检查 `~/.dsh/uniterminal/profiles.json`：该主机 `auth` 里**只有 `identityPath` 路径字符串，没有任何密钥内容**

## 判据 4 · 私钥口令与错误路径
1. 若私钥带口令：填「私钥口令（可选）」→ 连接应成功
2. 把路径改成不存在的文件 → 连接应提示「私钥文件读不到，请检查路径…」，**不是 500、不是空白**
3. 选私钥模式但路径与粘贴都空着 → 应提示「尚未配置私钥：请填写路径或粘贴私钥内容」

## 判据 5 · 粘贴私钥方式（可选）
1. 选私钥 → 路径留空 → 点「粘贴私钥内容」→ 贴入私钥 → 保存 → 连接应成功
2. 保存成功后 textarea 应**立即清空**（私钥不滞留在界面状态里）

## 已知限制

- 私钥内容**永不回填界面**：粘贴过的私钥只在宿主凭据库里，界面不会再显示
- Windows 上 `credentials.json` 的 0600 无效，依赖用户目录 NTFS ACL
- 无终端锁屏（离开座位保护）——你已决定暂缓
- `M1-15b`（进终端后偶发掉回主机页）仍未定位
